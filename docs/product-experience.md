# 0.3.0 用户流程调整

目标用户只需要安排“让 AI 做什么、什么时候做、结果发给谁”。本次按这个顺序调整界面，没有增加调度能力。

## 主要问题与改动

| 原来的障碍 | 新的处理 |
| --- | --- |
| 一开始就要求理解会话、投递、绑定和同步 | 三步完成：安排工作、接收结果、确认创建 |
| 全局同步开关占据首页，容易误认为是所有任务的总开关 | 放入“聊天发送设置”，仅在已有聊天模式提示影响 |
| 标题、机器人、接收目标、目录全部要自己选 | 标题自动生成；唯一选项自动选中，多选项不猜测 |
| 编号和完整路径难以辨认 | 显示平台中文名、机器人短标识、工作区名称；完整编号放入更多信息 |
| 创建按钮变灰但不知道缺什么 | 下一步给出可行动的提示，缺少机器人、目标或聊天时指出设置位置 |
| 点击就创建，不清楚具体安排 | 最后展示执行时间、接收位置及记录归属，确认后才提交 |
| 列表被已结束任务占满 | 主要显示进行中的任务，结束记录折叠保留 |

两种记录方式仍由用户选择：默认“单独保存任务记录”，另一种为“放进已有的聊天记录”。已有任务的记录归属不能改变，界面不承诺迁移。原来的任务 ID、配置和发送去重全部保留。

## 验证边界

界面测试验证分步校验、返回保留输入、唯一选项默认选择、确认前不创建、重复点击保护，以及聊天发送关闭时明确提示。原生调度、冷恢复和工具调用最终结果等集成回归继续运行。

这属于产品流程改进与实现检查，尚未进行普通用户的独立可用性测试。后续验收应让未参与开发的人在不看文档的情况下创建一项每日任务，观察卡住的位置、是否能解释结果发到哪里、是否能找到执行记录；不能用开发者自己的操作代替该测试。

## 0.3.2 收敛

按用户最终决定，新任务只使用“独立保存执行记录，完成后发送到 IM”这一种方式。0.3.0 中的记录方式选择和聊天发送设置均已移除，不再把执行机制交给普通用户选择。旧版聊天任务只保留兼容与说明，不提供新建入口或自动迁移。
