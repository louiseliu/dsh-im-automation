## 优先改进项

| 优先级 | 实际观察 | 普通用户可能的理解 | 建议 |
| --- | --- | --- | --- |
| P1 | 机器人显示“飞书机器人 · ea8b”，接收人显示“私聊 · ou_28…f3eb” | 不知道哪个是自己的机器人、消息会发给谁 | 优先显示已配置的真实名称；缺少名称时提示设置备注；确认页突出“通过谁，发给谁” |
| P1 | 要求选择“机器人平时使用的工作区” | 用户未必知道机器人配置了哪个资料目录 | 在接口能确定时自动带出，并显示“使用某工作区的资料”；无法确定时才让用户选择，不能暗中猜测 |
| P1 | 首次执行前“查看执行记录”进入欢迎页，左侧为“新会话” | 以为记录未保存，可能又创建一次 | 创建成功页显示“等待首次执行”和具体时间；首次运行前将记录入口说明清楚，避免直接进入无说明的空白页 |
| P1 | 一次性任务完成后首页显示“还没有正在运行的任务”，本任务收进折叠区 | 以为刚创建的任务不见了，找不到是否发成功 | 首页保留最近完成的任务和发送结果，再折叠更早历史；将最近执行放在前面 |
| P2 | 创建成功后立即出现整套接收设置、保存按钮、测试发送按钮 | 不确定刚才是否已经保存，还要不要再保存、测试 | 成功页先展示“已安排”摘要和查看结果入口；编辑与测试操作放到次要位置 |
| P2 | 确认页仅显示“1 分钟后执行一次” | 不确定从哪一刻计时；等待时不知道确切时间 | 创建后明确显示完整的下次执行时间；“只做一次”后续可增加指定日期时间 |

建议先解决名称辨认、自动匹配工作区和创建后的等待/完成反馈，再扩充时间选项。本次只验证与记录，没有修改产品代码。
